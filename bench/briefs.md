# bench/briefs.md — the standing brief set

> Real product-decision prompts, tagged by difficulty, used to run the self-test.
> The mix matters: **easy** briefs test the ceremony tax (the Ritual should ~tie,
> never lose); **hard** briefs are where it should pull ahead. Add your own *actual*
> product decisions — that's where the test gets honest. Keep each to one line so
> the conditions all start from exactly the same place.

> **Difficulty:** `easy` = a mostly-known answer / reversible · `med` = a real
> trade-off · `hard` = open-ended, taste-heavy, hard-to-reverse, systemic.

## Notes

- **Replace these with your own decisions over time.** Generic briefs prove the
  framework on generic work; *your* briefs prove it on the work you actually do.
- Keep a stable core set so results stay comparable run-to-run; add new briefs in
  their own batch and record them separately.
- For each brief the harness records: the winner per condition, dimension scores,
  and difficulty — so the easy/hard split (the ceremony-tax signal) falls out for free.
